# KITH Carbon Fields и Polylang

[English](../polylang.md) · [Оглавление](index.md)

Активируйте Polylang и настройте языки сайта. Настройки темы по языкам доступны с KITH Carbon Fields 3.6.11.10. Режимы перевода полей записи и общие значения для отдельных настроек появились в 3.6.11.11.

## Перевод настроек темы

Откройте страницу настроек Carbon Fields и выберите язык во вкладках или на верхней панели Polylang. Вкладка **Общие значения** соответствует пункту **Все языки** на панели. Здесь задаются значения для языков, у которых ещё нет собственных.

Настройки, сохранённые до подключения интеграции, становятся общими. Язык наследует поле целиком до первого сохранения своего значения. Пустая строка, снятый флажок, пустой набор и пустой комплекс считаются сохранёнными значениями. Комплекс читается целиком из одного языка или из общих настроек.

Сохранение вкладки языка может записать и показанные в ней унаследованные значения. Используйте `sync` для поля, которое всегда должно брать общее значение.

Форма сохраняется на языке, на котором её открыли. Если этот язык удалили, откройте страницу настроек заново и выберите доступный язык. После отключения Polylang сайт использует общие значения. Локализованные значения снова доступны после активации.

### Общее поле или целая страница настроек

Укажите `set_translation( 'sync' )` у поля верхнего уровня, чтобы у него было одно значение для всех языков. Например, это удобно для номера телефона. Если общими должны быть все поля страницы, используйте `set_multilingual( false )` у контейнера.

```php
use Carbon_Fields\Container;
use Carbon_Fields\Field;

add_action( 'carbon_fields_register_fields', function () {
    Container::make( 'theme_options', 'Footer settings' )
        ->add_fields( array(
            Field::make( 'text', 'kith_footer_text', 'Footer text' )
                ->set_visible_in_rest_api( true ),
            Field::make( 'text', 'kith_footer_phone', 'Phone' )
                ->set_translation( 'sync' ),
        ) );

    Container::make( 'theme_options', 'Integration settings' )
        ->set_multilingual( false )
        ->add_fields( array(
            Field::make( 'text', 'kith_integration_key', 'Integration key' ),
        ) );
} );
```

При переключении уже переведённой настройки в `sync` явно задайте общее значение. Ранее сохранённые переводы остаются в базе. Режимы `copy_once` и `independent` управляют переводами записей. В настройках темы оба используют обычное хранение по языкам.

### Чтение и запись настроек темы из PHP

Обычный вызов использует текущий язык контента. Передайте настроенный в Polylang код языка, если нужно выбрать его явно, например в задании по расписанию. Значение `all` указывает на общую настройку. Пустой аргумент в примере позволяет найти поле без указания ID контейнера.

```php
$footer = carbon_get_theme_option( 'kith_footer_text' );
$english_footer = carbon_get_theme_option( 'kith_footer_text', '', 'en' );
$shared_footer = carbon_get_theme_option( 'kith_footer_text', '', 'all' );

carbon_set_theme_option( 'kith_footer_text', 'Contact us', '', 'en' );
```

### Настройки темы через REST

Выполняйте запрос от имени пользователя WordPress с правом `manage_options`. Чтобы поле попадало в ответ на чтение, укажите `set_visible_in_rest_api( true )`. Код языка или `all` передаётся в параметре `lang`.

```http
GET /wp-json/carbon-fields/v1/options/?lang=en
```

```http
POST /wp-json/carbon-fields/v1/options/?lang=en
Content-Type: application/json

{"kith_footer_text":"Contact us"}
```

В теле POST передаются пары «имя поля — значение». Если язык неизвестен, API вернёт HTTP 400 до сохранения.

## Режимы перевода полей записи

Зарегистрируйте поля в контейнере `post_meta`, который применяется к переведённому типу записи. Добавляйте перевод штатными средствами Polylang в редакторе.

| Режим | При создании перевода | После создания |
| --- | --- | --- |
| `copy_once` (по умолчанию) | Копирует исходное поле, когда в переводе ещё нет сохранённого значения. | У каждого перевода своё значение. |
| `sync` | Копирует исходное поле, когда в переводе ещё нет сохранённого значения. | При редактировании синхронизирует поле между связанными переводами. |
| `independent` | Пропускает начальное копирование. Поле может получить заданное значение по умолчанию. | У каждого перевода своё значение. |

```php
use Carbon_Fields\Container;
use Carbon_Fields\Field;

add_action( 'carbon_fields_register_fields', function () {
    Container::make( 'post_meta', 'Contact details' )
        ->where( 'post_type', '=', 'page' )
        ->add_fields( array(
            Field::make( 'text', 'kith_contact_subtitle', 'Subtitle' )
                ->set_translation( 'copy_once' ),
            Field::make( 'text', 'kith_contact_phone', 'Phone' )
                ->set_translation( 'sync' ),
            Field::make( 'textarea', 'kith_contact_note', 'Local note' )
                ->set_translation( 'independent' ),
        ) );
} );
```

Указывайте режим у поля верхнего уровня. Для комплекса он применяется ко всей структуре, включая вложенные строки. При синхронизации комплекс считается одним полем.

### Сохранение из нескольких вкладок

Допустим, открыты два перевода с одним номером телефона. Измените телефон в первой вкладке, затем сохраните только подзаголовок во второй. В обоих переводах будет новый телефон. Новый подзаголовок появится во втором переводе. Если отредактировать одно и то же общее поле в обеих вкладках, применяется последнее успешное сохранение. Это относится и к двум правкам внутри одного общего комплекса.

Редактор сравнивает отправленное значение с тем, которое было при открытии вкладки или при последнем сохранении из неё. После обновления плагина откройте старые вкладки заново, чтобы загрузилась актуальная форма.

### Требования к синхронизации

Поле записи должно использовать стандартное хранилище метаданных Carbon Fields и применяться к участвующим записям. Текущий пользователь WordPress должен иметь право их редактировать. Общие поля сохраняются в одной транзакции для исходной записи и переводов. Для этого нужны таблицы записей и метаданных на InnoDB, соединение через MySQLi и совместимые хуки записи метаданных. При ошибке запись общего поля откатывается во всех переводах.
