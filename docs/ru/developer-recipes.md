# Фильтры каталога, создание записей и кеширование шаблонов

[English](../developer-recipes.md) · [Справочник PHP API](developer-api.md)

## Условия запроса из параметров URL

Вызывайте `carbon_parse_post_filters( $post_type, $input, $filters, $container_id = '' )` после регистрации полей. В PHP перечислите допустимые параметры URL и укажите соответствующие корневые поля. Передайте массив без экранирования WordPress, например `wp_unslash( $_GET )`.

Для примера объявите `price` как текстовое поле с `type=number`, а `delivery` как `select` с ключами `pickup` и `courier`. Проект также регистрирует тип записи `service` и поле `status` с вариантом `active`.

```php
$parsed = carbon_parse_post_filters( 'service', wp_unslash( $_GET ), array(
    'min_price' => array( 'field' => 'price', 'compare' => '>=' ),
    'max_price' => array( 'field' => 'price', 'compare' => '<=' ),
    'delivery'  => array( 'field' => 'delivery', 'multiple' => true ),
) );

if ( is_wp_error( $parsed ) ) {
    echo esc_html( $parsed->get_error_message() );
    return;
}

$args = array(
    'post_type'      => 'service',
    'post_status'    => 'publish',
    'posts_per_page' => 20,
    'paged'          => max( 1, (int) get_query_var( 'paged' ) ),
    'carbon_fields'  => array(
        'where'   => array_merge(
            array( array( 'field' => 'status', 'value' => 'active' ) ),
            $parsed['where']
        ),
        'orderby' => array( 'price' => 'ASC' ),
    ),
);
$services = new WP_Query( $args );
$minimum_selected = $parsed['values']['min_price'] ?? '';
```

`where` содержит условия для `WP_Query`. В `values` лежат выбранные значения по именам параметров URL. Их можно использовать, чтобы восстановить состояние формы фильтра. Дробные числа возвращаются строками для сохранения точности. Запрос `?min_price=0&delivery=pickup` включает нижнюю границу `0` и условие `IN` для самовывоза. Несколько вариантов передаются через `delivery[]=pickup&delivery[]=courier`.

Для одиночных числовых фильтров доступны `=`, `>=`, `<=`, `>` и `<`. По умолчанию используется `=`. Параметр `multiple` формирует условие `IN` и возвращает массив уникальных значений. Для обычного `select` допустимые ключи берутся из текущих вариантов поля. Для серверного списка, зависимого списка или другого нечислового поля задайте массив разрешённых ключей через `choices`. Пустые и необъявленные параметры пропускаются. Недопустимое значение возвращает `WP_Error` с именем параметра в `parameter`. При неоднозначном имени поля передайте ID контейнера парсеру и в `carbon_fields['container_id']`.

Если для одного числового поля указаны обе включительные границы цены, в `where` попадёт один `BETWEEN` с двумя десятичными строками. Оба значения для формы сохраняются в `values`. Если задана одна граница, остаётся её условие. Пара включительных границ также объединяется при прямой передаче условий в `WP_Query`.

## Счётчики вариантов и диапазоны

`carbon_get_post_facets( $args, $facets )` учитывает тип и статус записей, поиск, таксономии и фильтры по полям. Для каждого показателя исключаются его собственные условия из `carbon_fields['where']`. Если выбран самовывоз, счётчики доставки по-прежнему показывают доступные варианты курьера. Диапазон цен игнорирует выбранные границы цены, сохраняя ограничение по доставке. Сортировка и пагинация пропускаются, чтобы расчёт охватывал все подходящие записи.

```php
$facets = carbon_get_post_facets( $args, array(
    'delivery' => 'choices',
    'price'    => 'range',
) );

if ( ! is_wp_error( $facets ) ) {
    $pickup_count = $facets['delivery']['pickup'] ?? 0;
    $minimum_price = $facets['price']['minimum'];
    $maximum_price = $facets['price']['maximum'];
}
```

Режим `choices` возвращает число записей для каждого сохранённого ключа. Повтор того же ключа в одной записи считается один раз. При выводе формы берите подписи из вариантов каталога. Режим `range` доступен для числовых полей и возвращает `minimum` и `maximum` как десятичные строки. При отсутствии подходящих чисел обе границы равны `null`. Сохранённый ноль учитывается, а пустые, отсутствующие и нечисловые цены пропускаются. Значение по умолчанию учитывается после сохранения.

Используйте аргументы обычного `WP_Query` вместе с условиями `carbon_fields`. Штатные условия в `meta_query` действуют для каждого расчёта. При промахе кеша выполняется один запрос агрегирования для поля. Повторный запрос берёт из кеша счётчики или диапазон. Переход на другую страницу и изменение фильтра, который фасет исключает из своего расчёта, позволяют переиспользовать его результат. Если поисковая интеграция заменяет штатный SQL отдельным набором результатов, метод возвращает `WP_Error`.

`carbon_get_post_facets( $args, $facets, $cache_ttl = 300 )` по умолчанию хранит результаты в транзиентах WordPress пять минут. Третий аргумент задаёт время в секундах. Передайте `0`, чтобы пересчитывать результаты при каждом вызове. Ключ учитывает итоговый SQL, сайт, пользователя и язык. Изменения записей, их метаданных, терминов и связей с таксономиями сбрасывают кеш фасетов сайта. При сохранении через Carbon Fields кеш сбрасывается после успешной записи. При откате пакета прежний кеш остаётся доступен.

После импорта через прямой SQL вызовите `clean_post_cache( $post_id )` после фиксации транзакции, чтобы сбросить старые результаты фасетов.

### Замер на 20 000 записей

Локальный стенд использовал WordPress 7.1.4, PHP 8.4.4 и MySQL 8.0.43 со штатными индексами WordPress. В наборе было 20 000 записей и 200 000 строк метаданных. В таблице приведены медианы прогонов на прогретой базе. Внутренний объектный кеш WordPress очищался перед каждым замером. Запрос списка возвращал 24 ID, а запрос фасетов рассчитывал два набора счётчиков и один диапазон цен.

| Операция | 3.6.11.32 | С объединением границ и кешем фасетов |
| --- | ---: | ---: |
| Фильтрация и сортировка списка | 401 мс | 311 мс |
| Расчёт трёх фасетов при промахе кеша | 1 568 мс | 1 192 мс |
| Повторный запрос фасетов | 1 568 мс | 3,85 мс |

Список ID, счётчики и границы цен совпали. В запросе списка осталось три соединения с таблицей метаданных вместо четырёх. Повторный запрос выполнил ноль SQL-агрегаций. Во время замера WordPress загружал значения из кеша. После изменения цены через WordPress фасет сразу вернул новый максимум `1500.25`.

## Создание записи с проверкой полей

`carbon_insert_post( $post, $fields, $container_id = '' )` возвращает ID записи или `WP_Error`. Передавайте значения без дополнительного экранирования. У текущего пользователя должно быть право создать запись этого типа. Публикация и сохранение приватной записи требуют права публикации. Если указан родитель, пользователь должен иметь право его редактировать.

```php
$id = carbon_insert_post(
    array(
        'post_type'   => 'service',
        'post_title'  => 'Экспресс-консультация',
        'post_status' => 'publish',
    ),
    array( 'status' => 'active', 'price' => '75.50', 'delivery' => 'pickup' )
);

if ( is_wp_error( $id ) ) {
    $error_data = (array) $id->get_error_data();
    $field_path = $error_data['path'] ?? array();
    echo esc_html( $id->get_error_message() );
}
```

Сначала создаётся черновик, затем плагин проверяет подходящие объявления и сохраняет переданные значения пакетом. Видимые обязательные поля проверяются и при отсутствии в массиве. Заполненное значение по умолчанию может удовлетворить обязательное поле. Числовые текстовые поля проверяются по объявленным `min`, `max` и `step`, а ключи списков — по их вариантам. Ошибка валидации может содержать путь `path`, а ошибка поиска поля — имя `field`. Поддерживаются итоговые статусы `draft` по умолчанию, `pending`, `publish` и `private`. Можно указать ID контейнера, чтобы ограничить проверку и запись его полями.

Итоговый статус устанавливается после сохранения полей. При ошибке проверки или смены статуса плагин удаляет черновик. Если фильтр WordPress блокирует удаление, ошибка `carbon_fields_post_cleanup_failed` содержит ID записи и сведения об исходной ошибке. Пакетная запись использует штатное транзакционное хранилище метаданных записи. При создании черновика возможны вызовы хуков WordPress. Внешние эффекты, например отправку писем и вебхуков, обработчики контролируют отдельно.

## Кеш фрагмента с зависимостями от полей

`carbon_cache_fragment( $key, $dependencies, $render, $ttl = HOUR_IN_SECONDS )` кеширует результат функции через транзиенты WordPress. Укажите корневые поля по ID записи и настройки темы, которые читает фрагмент.

```php
$html = carbon_cache_fragment(
    'service-price:' . $post_id,
    array(
        'post_meta'     => array( $post_id => array( 'price' ) ),
        'theme_options' => array( 'currency' ),
    ),
    static function() use ( $post_id ) {
        return '<span class="service-price">' . esc_html(
            carbon_get_post_meta( $post_id, 'price' ) . ' ' . carbon_get_theme_option( 'currency' )
        ) . '</span>';
    },
    15 * MINUTE_IN_SECONDS
);

if ( ! is_wp_error( $html ) ) {
    echo $html; // Динамический текст экранирован в функции вывода.
}
```

Успешное сохранение изменившегося значения Carbon Fields сбрасывает связанный кеш. Укажите имя корневого комплекса, чтобы отслеживать его содержимое целиком. Изменение отслеживаемой настройки темы на любом языке сбрасывает кеш всех её языковых вариантов. В ключе уже учитываются сайт и текущий язык. Если вывод зависит, например, от роли или валюты в пользовательской сессии, добавьте этот признак в ключ.

Время жизни задаётся положительным числом секунд. Если функция вывода возвращает `WP_Error`, он передаётся вызывающему коду. Отслеживаются события сохранения Carbon Fields. После прямой записи в БД или изменения других данных WordPress, например заголовка записи, фрагмент может оставаться в кеше до конца заданного срока.

## Вывод ссылок и кнопок

`carbon_link( $value, $attributes = array() )` принимает структурированное значение поля `link`, в том числе из настроек темы или строки комплекса. Для внутренней ссылки функция получает актуальный адрес записи и возвращает готовую HTML-ссылку или пустую строку.

```php
echo carbon_link( carbon_get_theme_option( 'header_cta' ), array(
    'class' => 'button button-primary',
    'data-placement' => 'header',
) );

echo carbon_link( $row['details_link'] ?? null, array(
    'label' => __( 'Подробнее', 'my-theme' ),
    'class' => 'service-link',
    'rel'   => 'nofollow',
) );
```

`label` переопределяет подпись обычным текстом. Поддерживаются атрибуты `id`, `class`, `title`, `rel`, `aria-*` и `data-*`. Флаг новой вкладки добавляет `target="_blank"` вместе с `noopener noreferrer`. Для вывода нужны подпись и действительный HTTP(S)-адрес. Если внутренняя запись удалена, недоступна публично или защищена паролем, результат будет пустым.

## Расширение объявления полей из другого модуля

Хук `carbon_fields_extend_fields` срабатывает после всех обработчиков `carbon_fields_register_fields` и до инициализации контейнеров. Используйте ID из `$container->get_id()`. В примере контейнер «Service details» содержит список `delivery` и комплекс `offices`. В группе `pickup` уже объявлено поле `region`.

```php
use Carbon_Fields\Field;

add_action( 'carbon_fields_extend_fields', function() {
    $container_id = 'carbon_fields_container_service_details';

    carbon_extend_field( $container_id, 'delivery', array(
        'label'     => __( 'Способ доставки', 'my-site' ),
        'help_text' => __( 'Выберите, как клиент получит заказ.', 'my-site' ),
        'options'   => array( 'locker' => __( 'Постамат', 'my-site' ) ),
    ) );

    carbon_insert_fields( $container_id, 'offices:pickup/region', array(
        Field::make( 'text', 'terminal', __( 'Терминал', 'my-site' ) ),
    ), 'after' );
} );
```

Позиция `before` вставляет поля перед указанным полем, `after` — после него. Новые поля получают ту же вкладку или секцию настроек темы вместе с её правилами доступа. Передавайте новые экземпляры из `Field::make()` с уникальными именами в пределах контейнера или группы. Для глубокой вложенности разделяйте уровни символом `/`, например `offices:pickup/branches:local/address`. Для безымянной группы опустите имя группы, как в `offices:pickup/branches/address`. Изменение объявления применяется ко всем строкам этого типа.

Ключ `options` работает со списками, варианты которых заданы в PHP. Повторный ключ в ассоциативном массиве обновляет подпись варианта. Для серверных и зависимых списков действуют их источники вариантов. Обе функции возвращают `true` или `WP_Error`.

## Создание и обновление записи по внешнему ID

Объявите корневое текстовое поле с `set_unique()` в контейнере метаданных записи. Для примера добавьте `Field::make( 'text', 'crm_id' )->set_unique()->set_normalizer( 'trim' )` вместе с `service_price` в контейнер «Service details».

```php
$result = carbon_upsert_post(
    'crm_id',
    $record['id'],
    array( 'post_type' => 'service', 'post_title' => $record['title'] ),
    array( 'service_price' => $record['price'] ),
    'carbon_fields_container_service_details'
);

if ( is_wp_error( $result ) ) {
    return $result;
}

$post_id = $result;
```

При успехе функция возвращает ID записи WordPress. Нормализованный внешний ID уникален в пределах типа записи. Передавайте его отдельно от изменений других полей того же контейнера. Если поле ID объявлено в нескольких контейнерах, укажите ID нужного контейнера. Новая запись по умолчанию создаётся как черновик и должна пройти проверку обязательных полей выбранного контейнера. При обновлении пропущенные атрибуты и поля сохраняют прежние значения. Действуют обычные права WordPress, условия доступности полей и валидаторы PHP API.

Запускайте функцию после регистрации полей от имени пользователя с нужными правами. Для записи нужны штатные таблицы записей и метаданных InnoDB и одно соединение с пишущей базой. Вызовы для одного нормализованного ID выполняются по очереди. Вызывайте функцию вне открытой транзакции. При ошибке `carbon_fields_upsert_busy` вызов можно повторить. Ошибка `carbon_fields_duplicate_external_id` означает, что в базе уже есть несколько записей с таким ID. Обновление в этом случае не выполняется.

## Генерация типизированного чтения для PHPStan и IDE

Сгенерируйте PHP-класс для зарегистрированного контейнера метаданных записей. Опция `--fields` принимает имена нужных корневых полей через запятую. Сохраните вывод в UTF-8 без BOM и подключите класс через автозагрузчик проекта.

```sh
wp carbon-fields generate-types carbon_fields_container_service_details 'Project\ServiceFields' --fields=service_price,offices > ServiceFields.php
```

В PowerShell 7 передайте вывод в `Set-Content -Encoding utf8NoBOM ServiceFields.php`, чтобы явно указать кодировку. В PHP можно вызвать `carbon_generate_post_field_types( $container_id, 'Project\\ServiceFields', array( 'service_price', 'offices' ) )`. Функция возвращает PHP-код или `WP_Error`.

```php
$fields = \Project\ServiceFields::get( $post_id, true );

if ( $fields ) {
    foreach ( $fields['offices'] as $office ) {
        if ( 'pickup' === $office['_type'] ) {
            echo esc_html( (string) $office['region'] );
        }
    }
}

$by_post_id = \Project\ServiceFields::get_many( $post_ids );
```

Класс использует существующие функции чтения одной и нескольких записей. У обоих методов второй аргумент включает предзагрузку медиа. PHPStan определяет состав полей по `_type` строки комплекса, в том числе на вложенных уровнях. Для незнакомых типов полей используется `mixed`. Псевдоним типа `Fields` можно подключить в другом классе через `@phpstan-import-type`. После изменения объявлений или их расширений сгенерируйте класс заново.
